# Краткая карта ETL S2T Parser

Этот файл — короткая точка входа для передачи проекта другой модели. Полное пользовательское описание, установка, схема данных и список инструментов находятся в `README.md`; обязательные правила разработки — в `AGENTS.md`. Не дублируйте их здесь.

## Назначение

Flask-приложение разбирает Excel-книги с Source-to-Target-маппингами, сохраняет исходные факты и результаты извлечения в SQLite, строит опциональную Neo4j-проекцию lineage и отвечает через инструментального LangGraph-агента.

## Основной поток

1. `processing/excel.py` разбирает листы и заголовки.
2. `storage/database.py` сохраняет структуру и исходные значения в SQLite.
3. `agents/sheet_group_classifier.py` выбирает группы листов.
4. Обработчики `sheet_skills/` записывают каталоги и S2T-строки.
5. `agents/summarizer_agent.py` одним LLM-вызовом строит описание файла.
6. `services/graph_sync.py` проецирует табличный и колонковый lineage в Neo4j.
7. `agents/agent.py` запускает read-only чатовый граф.

## Агентная часть

`agents/tools/routing.py` отдельным обычным LLM-вызовом выбирает точные имена tools и runtime skills. Модель возвращает сырой JSON, который приложение строго валидирует. Эвристического fallback нет.

`agents/chat_graph.py` выполняет цикл planner → tool → observer → planner/responder. Следующий planner и responder получают исходные `ToolMessage`; observer возвращает компактный обычный текст без structured output. Skills загружаются лениво и независимо от tools.

SQLite остаётся источником фактов. Neo4j содержит производную проекцию `ETLTable`/`TABLE_TRANSFORMS_TO` и `ETLColumn`/`TRANSFORMS_TO`; отсутствие данных в графе не доказывает их отсутствия в SQLite.
