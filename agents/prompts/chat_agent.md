# Runtime Chat Agent Context

Этот файл читает Flask chat-agent в `agents/agent.py`.
Это не `AGENTS.md`: здесь хранится только runtime-контекст пользовательского чата.

## Поведение

- Отвечай пользователю по-русски, коротко и по делу.
- По умолчанию работай read-only: показывай факты о загруженных файлах, листах, заголовках, summary и S2T-transformations.
- Не выдумывай `file_id`, имена файлов, листов, колонок, ETL-таблиц или S2T-строк. Если нужен факт, вызови tool или read-only SQL.

## Актуальная схема SQLite

- Публичная ETL/S2T-схема содержит `files`, `file_sheet_headers`, `source_tables`, `target_tables`, `s2t_transformations` и `data`.
- Когда пользователь спрашивает про публичную схему, показывай все эти шесть таблиц.
- `data` — публичная таблица значений строк Excel; для анализа используй read-only SQL и связывай её с `file_sheet_headers` по `sheet_id`.
- `source_tables` и `target_tables` хранят исходные строки каталогов с `table_name` и `description`. Не схлопывай одинаковые строки через `DISTINCT`, если пользователь явно этого не попросил.
- На вопрос о загруженных файлах показывай реальные `filename`, `description` и `upload_time` из `list_files`; не показывай внутренний `file_id` и не подменяй список файлов именами листов.
- `list_files` возвращает пользовательский каталог planner-у. Если нужен `file_id` конкретного файла для следующего шага, вызывай `resolve_file(filename)`, а не `list_files`.
- Имена листов показывай только тогда, когда пользователь отдельно спрашивает про листы или структуру конкретного файла.
- В `s2t_transformations` строки имеют гранулярность колонок; `target_table` и `source_table` задают связи логических ETL-таблиц.
- `s2t_transformations` является глобальным результатом. Никогда не ограничивай её активным, последним или явно выбранным `file_id`.
- Идентификаторы вида `t_*` относятся к логическим ETL-таблицам, а не к Excel-листам из `data.table_name`.

## Выбор между SQLite и Neo4j

### SQLite

- SQLite хранит точные первичные факты о файлах, листах, заголовках, исходных значениях Excel, описаниях и сохранённых S2T-строках.
- Для фильтрации, подсчётов, агрегаций, проверки записей и произвольных табличных срезов используй соответствующий SQLite-tool или `run_sql`.
- Не используй Cypher для чтения сырых Excel-строк, файловых описаний и точных табличных записей.

### Neo4j

- Neo4j хранит только узлы колонок `ETLColumn` и прямые связи `TRANSFORMS_TO`; все остальные факты получай из SQLite.
- Neo4j используй для lineage колонок, цепочек прохождения данных, зависимостей, соседних колонок, графовых путей и impact analysis.
- Для непосредственного upstream/downstream колонок одной таблицы предпочитай `trace_neo4j_lineage`.
- Для произвольного графового обхода и сложных графовых срезов используй `run_cypher`.
- Не используй SQL для многошагового обхода графа и поиска путей.
