# Доменные навыки read-only chat-agent

Skills задают оркестрацию tools. Атомарные контракты tools — аргументы, ограничения,
результат и ошибки — задаются только descriptions и схемами tools.

## S2T-строки

- Точное полное source_table/target_table: `list_s2t_transformations`; фрагмент
  или имя без схемы: `search_s2t_transformations`, независимо от известной роли.
- В `list_s2t_transformations.q` передавай только одну буквальную подстроку, не
  склеивай несколько имён или условий. Для точной пары полей внутри известных
  таблиц получи строки по ролевым table-фильтрам и выбери совпавшую пару; для
  нестандартного точного среза или агрегации используй `run_sql`.
- Явно названные `target_table`/`target_field` или
  `source_table`/`source_field` всегда передавай ролевыми фильтрами
  `list_s2t_transformations`; не склеивай их в needle подстрочного поиска.
- Для проверки покрытия конечного известного набора полей не нужен полный дамп
  S2T: точное наличие маппинга каждого поля достаточно. Поле считается
  немаппированным только когда точный ролевой запрос по нему вернул 0 строк.
- Списки и операции множеств source/target: `list_s2t_table_names`; он сам
  гарантирует корректную принадлежность имени ролям.
- `source_only` и `target_only` уже являются готовыми разностями множеств: не
  вычисляй противоположную роль вторым вызовом и не перепроверяй их через SQL.
- Для количества маппингов, полей и связанных таблиц по одной основной роли
  используй `summarize_s2t_tables`.
- Для произвольного среза или нестандартной агрегации используй `run_sql`.
- Для готового графа всех табличных связей используй
  `visualize_s2t_table_graph`, не вызывая перед ним невизуальные аналоги.
- s2t_transformations глобальна и никогда не ограничивается активным file_id.
- При сравнении каталога target-колонок с S2T сопоставляй `column_name` только с
  `target_field` и сохраняй фильтр `target_table`; для source-колонок используй
  только `source_field`/`source_table`. Не подменяй роли друг другом.
- «Трансформация» и «правило трансформации» означают `transformation_rule`.
- Получив сохранённый `transformation_rule`, анализируй сам текст правила; не
  запускай новый поиск S2T только для повторного подтверждения уже найденного SQL
  и не выполняй этот SQL через `run_sql`. Проверки наличия GROUP BY, DISTINCT,
  оконных функций, JOIN и WHERE являются анализом текста, а не проверкой строк
  внешней ETL-таблицы.
- Одинаковые исходные строки являются отдельными фактами и не дедуплицируются.

- `trace_transformation_path` возвращает правила, additional objects, схему и
  подтверждение Neo4j. Для фрагмента имени сначала добавь
  `search_s2t_transformations`; не дублируй путь отдельными list/Neo4j tools.
- Downstream: source_table/source_field; upstream: target_table/target_field.
  Шаги всегда показывай физически:
  `source_table.source_field → target_table.target_field`.
- `text_diagram` — готовая схема: перенеси её дословно.
- NULL, пустая строка и ровно «-» означают прямую трансформацию.
- `WHEN` внутри `CASE` выбирает значение; строки фильтруют `WHERE`, `HAVING` и
  ограничивающие `JOIN`. `UNION`/`UNION ALL` объединяет ветви, не агрегирует и
  само значение не преобразует.
- Строки с одинаковыми file_id, target_table, target_field и
  transformation_rule, но разными source_field — входы одного выражения:
  факты сохрани, но объясняй одну логическую трансформацию с несколькими входами.
- Отсутствие подтверждения Neo4j не отменяет факты SQLite.

## Neo4j

- Lineage колонки любой глубины: `trace_neo4j_lineage`; он объединяет точные
  связи и wildcard `* → *`.
- Wildcard — отдельный table-scoped `ETLColumn`; `COVERED_BY`/`EXPANDS_TO`
  связывают его с колонками. Шаг `* → *` переносит одноимённую запрошенную
  колонку: это перенос, не отсутствие маппинга. Рёбра показывай `source → target`.
- Прямой lineage таблицы: `trace_neo4j_table_lineage`; `table_exists` отличает
  отсутствующий узел от таблицы без подходящих рёбер.
- Путь между двумя таблицами: `trace_neo4j_table_path`; `chains` — точные
  цепочки, `paths` — полные рёбра.
- Для произвольного графового обхода таблиц, нескольких условий, группировки
  или нестандартного среза используй `run_cypher`.
- Neo4j является синхронизированной проекцией: пустой графовый результат не
  доказывает отсутствие объекта или связи в SQLite.
- Колонковые узлы ETLColumn связаны TRANSFORMS_TO, табличные ETLTable —
  TABLE_TRANSFORMS_TO.

## Excel и описания

- Для каталога загрузок используй `list_files`, а точное имя файла разрешай
  через `resolve_file` перед файловыми tools.
- Для листов и заголовков используй `list_sheets`,
  `list_file_sheet_headers` и `list_columns` по требуемому уровню детализации.
- Для поиска значения используй `search_excel_values`; если нужен контекст всей
  строки, следующим шагом вызови `get_excel_row` с фактическими идентификаторами
  из результата поиска.
- `search_excel_values` читает только сохранённые значения исходных Excel-ячеек
  из `data`. Не используй его для S2T, transformation_rule, SQL-признаков или
  физических строк логических ETL-таблиц.
- Семантика: `semantic_search_descriptions`; `scope`: `files`,
  `tables`, `source_tables`, `target_tables`, `columns`, `source_columns`,
  `target_columns` по домену, `all` — только без домена. Для колонок можно
  передать точные фильтры подвыборки до семантического ранжирования.
- Точные фильтры и выбранные поля каталога колонок: `list_column_catalog`;
  поиск фрагмента имени, типа или описания в подвыборке:
  `search_column_catalog`. Aliases физических заголовков исходных листов нужны
  только при загрузке и хранятся в `column_mapping.json`; в ETL-каталогах
  колонок aliases нет.
- Явное требование получить строки публичных `source_columns`/`target_columns`
  по точным фильтрам выполняй через `list_column_catalog`; общий `run_sql` для
  последующего вычисления не заменяет этот факт получения.
- В каждый `list_column_catalog` передавай все явно заданные точные фильтры этой
  операции. Нельзя опускать `table_name` и расширять выборку до всего файла.
  `scope` обязателен: используй `source_columns` или `target_columns` для явно
  известной роли, `all_tables` — только если нужны обе стороны или роль колонки
  неизвестна. Широкий scope не является обходом явно заданного `table_name`.
- Если source и target имеют разные table_name или column_name, получай их
  отдельными точными вызовами `list_column_catalog`; не ищи target по имени source.
- Не выдумывай file_id, имена файлов, листов, колонок и таблиц.
